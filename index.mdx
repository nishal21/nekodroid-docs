## Up and running in four steps

<Steps>
  <Step title="Install the tools">
    You need stable Rust with the `wasm32-unknown-unknown` target, wasm-pack, and Node.js `^20.19.0` or `>=22.12.0`.

    ```bash
    rustup target add wasm32-unknown-unknown
    ```
  </Step>
  <Step title="Clone and install">
    ```bash
    git clone https://github.com/nishal21/NekoDroid.git
    cd NekoDroid
    npm install
    ```
  </Step>
  <Step title="Build and start">
    <CodeGroup>
    ```bash Build Wasm
    wasm-pack build --target web
    ```
    ```bash Dev server
    npm run dev
    ```
    </CodeGroup>
    Then open [http://localhost:5173](http://localhost:5173).
  </Step>
  <Step title="Try it">
    <Tabs>
      <Tab title="ARM demo">
        In the **ARMv7 CPU Debug** panel, click **Load Demo**, then **Step**. After three steps, `R0`, `R1` and `R2` hold `5`, `10` and `15`.
      </Tab>
      <Tab title="Hello APK">
        Click **Load APK**, pick `testdata/hello.apk`, then **Run APK (HLE)**. The log shows:

        ```text
        Hello from NekoDroid
        ```
      </Tab>
    </Tabs>
  </Step>
</Steps>

## Good to know

<AccordionGroup>
  <Accordion title="Can it run apps from the Play Store?">
    No. Ordinary Play Store apps, multidex, JNI and Google Play Services are not supported. The APK runner is a constrained Dalvik interpreter, not a full Android system. See [APK compatibility](/android/supported-apks).
  </Accordion>
  <Accordion title="Does my code run on a server?">
    No. Everything runs locally in your browser through WebAssembly.
  </Accordion>
  <Accordion title="Do APKs run on the ARM CPU?">
    No. The two runtimes are separate. APK bytecode is parsed and run by the Dalvik HLE layer. Read [How it works](/how-it-works).
  </Accordion>
</AccordionGroup>
