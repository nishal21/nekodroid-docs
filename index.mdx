## Know Which Engine You're Using

| Your input | Execution path | What to expect |
| --- | --- | --- |
| ARM hex or a flat `.bin` | ARM / Thumb CPU | Registers, disassembly, RAM, and memory-mapped peripherals |
| A supported APK | Separate Dalvik HLE interpreter | Stubbed framework calls, log output, and placeholder glyphs |
| Linux kernel and optional initramfs | ARM CPU with boot setup | Experimental kernel execution, not a guaranteed complete boot |

<Note>
  NekoDroid is not a full Android OS. Ordinary Play Store apps, multidex, JNI libraries, and Google Play Services are not supported by the APK HLE runner. Check [APK compatibility](/android/supported-apks) before trying your own file.
</Note>

## Questions Before You Start

<AccordionGroup>
  <Accordion title="Do I need Android Studio to try the Hello APK?">
    No. The repository includes `testdata/hello.apk`. Build NekoDroid, select the file through **Load APK**, and click **Run APK (HLE)**. The expected log is `Hello from NekoDroid`.
  </Accordion>

  <Accordion title="Does APK bytecode run through the ARM CPU?">
    No. ARM emulation and Dalvik HLE are independent execution paths in the same Rust WebAssembly module. The [architecture guide](/how-it-works) explains how they connect to the browser.
  </Accordion>

  <Accordion title="What are the display size and memory defaults?">
    The framebuffer is 800 × 600 RGBA. Calling `init_emulator(0)` selects 512 MB of RAM; callers can choose another size. Large allocations may exceed a browser's available memory.
  </Accordion>
</AccordionGroup>
