This page covers every control in the NekoDroid ARMv7 CPU debug panel and explains how to use it.

## Load a Program

### Load Demo

Click **Load Demo** in the **ARMv7 CPU Debug** panel. The emulator writes a 10-instruction program to RAM at `0x8000`, sets `PC = 0x8000`, and resets the cycle count. The disassembly panel updates immediately.

The demo program executes the following:

| Address | Instruction | Effect |
| --- | --- | --- |
| `0x8000` | `MOV R0, #5` | `R0 = 5` |
| `0x8004` | `MOV R1, #10` | `R1 = 10` |
| `0x8008` | `ADD R2, R0, R1` | `R2 = 15` |
| `0x800C` | `SUB R3, R2, #1` | `R3 = 14` |
| `0x8010` | `CMP R3, #14` | Sets Z flag |
| `0x8014` | `BEQ` | Branches if equal |
| `0x8018` | `MOV R4, #1` | Not-taken path |
| `0x801C` | `B` | Skip to end |
| `0x8020` | `MOV R4, #0` | Taken path (equal) |
| `0x8024` | `NOP` | `MOV R0, R0` |

### Hello UART

Click **Hello UART** to load a hand-assembled program that prints "Hello World!" to the virtual serial port. After loading, press **Step** or **Run** to execute. The console shows the output when the newline byte flushes the buffer.

The program uses these instructions:

| Address | Instruction | Effect |
| --- | --- | --- |
| `0x8000` | `MOV R1, #0x10000000` | UART TX base address |
| `0x8004` | `ADD R2, PC, #0x18` | Point to string at `0x8020` |
| `0x8008` | `LDRB R0, [R2], #1` | Read byte, post-increment |
| `0x800C` | `CMP R0, #0` | Check for null terminator |
| `0x8010` | `BEQ halt` | Exit loop if null |
| `0x8014` | `STRB R0, [R1]` | Write byte to UART |
| `0x8018` | `B loop` | Repeat |
| `0x801C` | `B .` | Infinite loop (halt) |
| `0x8020` | `"Hello World!\n\0"` | ASCII payload |

## Step Through Instructions

- **Step** executes exactly one instruction and pauses
- **Run 10** executes up to 10 instructions or until the CPU halts
- **Run** enters continuous mode: it runs batches of one million instructions per frame until halted or stopped

The debug panel updates live during continuous execution.

## Read the Register Grid

Sixteen cells display `R0` through `R15`. Values are shown as 8-digit uppercase hex. Changed registers flash briefly. The aliases are:

- `R13` = `SP`
- `R14` = `LR`
- `R15` = `PC`

## Read the Flags Row

Five pills sit above the disassembly panel:

| Pill | Meaning | Set when |
| --- | --- | --- |
| N | Negative | Result bit 31 is 1 |
| Z | Zero | Result equals zero |
| C | Carry | Unsigned overflow or no borrow |
| V | Overflow | Signed overflow |
| ARM / THUMB | Current instruction set | `T` bit in CPSR |

## Read the Disassembly Panel

The disassembler shows the next five instructions starting at `PC`. The first line is highlighted as the current instruction. If an instruction is not recognized, the line shows the raw 32-bit encoding.

## Upload Custom Hex Programs

The **CUSTOM PROGRAM** textarea accepts space-separated ARM machine code hex words. Click **Upload to RAM** to write them at `0x8000` and reset `PC`.

### Placeholder Program

The default placeholder text is `e3a00005 e3a0100a e0802001`. Here is the breakdown:

| Hex | Disassembly | Meaning |
| --- | --- | --- |
| `e3a00005` | `MOV R0, #5` | Move `5` into `R0` |
| `e3a0100a` | `MOV R1, #10` | Move `10` into `R1` |
| `e0802001` | `ADD R2, R0, R1` | Add `R0` and `R1`, store `15` in `R2` |

After uploading and stepping three times, `R0 = 5`, `R1 = 10`, and `R2 = 15`.

All tokens must be exactly 8 hex characters. The parser accepts spaces and newlines.

## Boot State

When the emulator initializes, the CPU boots with:

| Register | Initial value |
| --- | --- |
| PC | `0x00008000` |
| SP | RAM size minus `0x10000` |
| All others | `0x00000000` |

Calling `init_emulator(0)` selects the 512 MB default. The maximum is 4096 MB. SP is always set to `RAM size - 0x10000`.

If you upload a `.bin` file, the ROM loader copies the binary to `0x8000` and sets `PC` there.
