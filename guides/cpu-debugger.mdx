NekoDroid ships with a built-in ARMv7 CPU debugger that runs entirely in the browser. You can step through instructions one at a time, inspect all 16 registers and the condition flags, view a live disassembly stream, and upload your own machine code or pre-built demos. This page covers every control in the debug panel and explains how the placeholder hex program works.

<Steps>
  ### Load a demo program

  1. Click **Load Demo** (boxed icon) inside the **ARMv7 CPU Debug** panel.
  2. The emulator writes a 10-instruction test program to RAM at `0x8000` and resets `PC` to the same address.
  3. The disassembly panel updates immediately and highlights `0x00008000` as the current instruction.

  This demo is useful for verifying that the fetch-decode-execute pipeline is alive before you load anything else.

  ### Run the Hello UART demo

  Click the green **Hello UART** button (terminal icon) to load a hand-assembled ARM program that prints text to the virtual serial port.

  The program performs the following operations:

  | Address  | Instruction           | Effect                                    |
  | -------- | --------------------- | ----------------------------------------- |
  | `0x8000` | `MOV R1, #0x10000000` | Load UART TX base address into `R1`       |
  | `0x8004` | `ADD R2, PC, #0x18`   | Point `R2` to the string at `0x8020`      |
  | `0x8008` | `LDRB R0, [R2], #1`   | Read next character, post-increment `R2`  |
  | `0x800C` | `CMP R0, #0`          | Check for null terminator                 |
  | `0x8010` | `BEQ halt`            | Exit loop if null                         |
  | `0x8014` | `STRB R0, [R1]`       | Write character to UART TX (`0x10000000`) |
  | `0x8018` | `B loop`              | Repeat for next byte                      |
  | `0x801C` | `B .`                 | Infinite loop (halt)                      |
  | `0x8020` | `"Hello World!\n\0"`  | ASCII payload, padded to 4-byte boundary  |

  After loading, press **Run 10** a few times, or press **Run** to execute continuously. The console log shows `📟 UART: Hello World!` when the newline byte flushes the buffer. The CPU halts at `0x801C` with a `B #+0` self-loop.

  ### Step through instructions

  * **Step** executes exactly one instruction and pauses.
  * **Run 10** executes up to 10 instructions or until the CPU halts.
  * **Run** (green play button) enters continuous mode: it runs one million instructions per animation frame until the CPU halts or you press the button again to stop.

  During continuous mode the debug panel still updates at 5 Hz (every 200 ms) so you can watch registers change without slowing the batch.

  ### Read the register grid

  Sixteen cells display `R0` through `R15` in a 4x4 grid. Values are shown as 8-digit uppercase hex. When a register changes, it flashes cyan for 300 ms so you do not miss updates during a burst of execution.

  The aliases are:

  * `R13` = `SP` (stack pointer)
  * `R14` = `LR` (link register)
  * `R15` = `PC` (program counter)

  ### Read the flags row

  Five pills sit above the disassembly panel:

  | Pill        | Meaning                 | Set when                       |
  | ----------- | ----------------------- | ------------------------------ |
  | N           | Negative                | Result bit 31 is 1             |
  | Z           | Zero                    | Result equals zero             |
  | C           | Carry                   | Unsigned overflow or no borrow |
  | V           | Overflow                | Signed overflow                |
  | ARM / THUMB | Current instruction set | `T` bit in CPSR                |

  A pill turns bright when the corresponding flag is set and stays dim when clear. The `ARM / THUMB` pill shows the current execution state; it switches automatically when the CPU executes a `BX` instruction with an odd target address.

  ### Read the disassembly panel

  The disassembler shows the next five instructions starting at the current `PC`. The first line is highlighted in cyan and labeled as the current instruction.

  NekoDroid's disassembler covers:

  * Data-processing instructions (`MOV`, `ADD`, `SUB`, `CMP`, `AND`, `ORR`, `EOR`, `BIC`, `MVN`) with barrel-shifter notation
  * Load/store (`LDR`, `STR`, `LDRB`, `STRB`, `LDRH`, `STRH`) with offset, pre-index, post-index, and writeback
  * Block transfers (`LDM`, `STM`, `PUSH`, `POP`)
  * Branches (`B`, `BL`, `BX`, `BLX`)
  * Multiply (`MUL`, `MLA`)
  * Software interrupt (`SWI`)

  If an instruction is not recognized, the line shows `UNIMPLEMENTED` and the 32-bit hex encoding.
</Steps>

## Upload custom hex programs

The **CUSTOM PROGRAM** textarea accepts space-separated ARM machine-code hex words. Click **Upload to RAM** to write them starting at `0x8000` and reset `PC`.

### Understanding the placeholder program

The placeholder text in the textarea is:

```text
e3a00005 e3a0100a e0802001
```

Each word is a little-endian 32-bit ARM instruction. Here is the breakdown:

| Hex | Disassembly | Meaning |
| --- | --- | --- |
| `e3a00005` | `MOV R0, #5` | Move immediate value `5` into register `R0` |
| `e3a0100a` | `MOV R1, #10` | Move immediate value `10` into register `R1` |
| `e0802001` | `ADD R2, R0, R1` | Add `R0` and `R1`, store the result (`15`) in `R2` |

After uploading and stepping three times, the register grid should read:

- `R0` = `00000005`
- `R1` = `0000000A`
- `R2` = `0000000F`

This is the same program used in the Rust unit test `test_basic_alu`.

### Tips for writing hex

<Note>
  All instructions must be 32-bit ARM machine code. Thumb (`T` = `1`) and data words are not accepted by the hex parser.
</Note>

<Tip>
  Use the disassembly panel to verify your upload. If a line does not decode the way you expect, double-check the endianness: NekoDroid stores instructions in little-endian byte order inside RAM, but the hex parser expects the natural word order you would see in an objdump listing.
</Tip>

<Warning>
  The hex parser is strict about whitespace and length. Each token must be exactly 8 hex characters. If you paste with newlines, make sure there are no extra spaces at the end.
</Warning>

## Boot-time state

When the emulator initializes with `init_emulator(0)` (512 MB default), the CPU boots with:

| Register | Initial value |
| --- | --- |
| PC | `0x00008000` |
| SP | RAM size minus `0x10000` (0x1FFF0000 for 512 MB) |
| All others | `0x00000000` |

If you upload a `.bin` file with **Select & Load .bin**, the ROM loader copies the binary to `0x8000` and sets `PC` to the same address. Custom hex uploads behave identically.
