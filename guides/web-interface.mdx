This page covers every panel and control in the NekoDroid browser UI so you know how to interact with the emulator and running programs.

## Status Bar

At the top of the page, a colored indicator shows the Wasm module state.

| Indicator | Meaning |
| --- | --- |
| Initializing Wasm module... | The Rust binary is still loading |
| Wasm loaded | The emulator is ready |
| Failed to load Wasm module | `wasm-pack` output is missing. Rebuild and refresh. |

## Canvas

The 800x600 pixel canvas is the main display. What it draws depends on the active render mode. Clicking or touching the canvas translates browser coordinates into framebuffer coordinates and forwards the event to the emulator. Audio also initializes on the first click because the Web Audio API requires a user gesture.

### Render Modes

Switch views with the buttons under the canvas:

| Button | Effect |
| --- | --- |
| **Noise** | Full-screen xorshift noise generated in Wasm |
| **Gradient** | Horizontal color sweep that shifts each frame |
| **Plasma** | Animated plasma field using sinusoidal color waves |
| **VRAM** | Displays what ARM programs write to `0x04000000` |
| **Pause** | Stops `requestAnimationFrame` updates but keeps the emulator alive |

When you load a bare-metal binary with **Select & Load .bin**, the UI automatically switches to VRAM mode.

## Metrics Panel

Four live counters sit above the console:

| Metric | What it measures |
| --- | --- |
| **FPS** | Frames drawn per second |
| **Frames** | Total `requestAnimationFrame` callbacks since startup |
| **CPU Cycles** | Total ARM instructions retired |
| **Mode** | Currently active render mode label |

## Console Log

A scrolling terminal below the metrics shows timestamped events from both the TypeScript frontend and the Rust backend. Types are color-coded: green for successes, blue for information, amber for warnings. The log keeps the last 100 lines.

## Debug Panel

The **ARMv7 CPU Debug** panel on the right contains execution controls and uploaders.

### Demo Buttons

- **Load Demo**: Loads 10 ARM instructions at `0x8000` that compute `R2 = R0 + R1`
- **Hello UART**: Loads a hand-assembled program that prints "Hello World!" to the virtual UART

### Execution Controls

- **Step**: Execute one instruction and update the register grid
- **Run 10**: Execute up to 10 instructions
- **Run / Stop**: Toggle continuous execution

### Register Grid

Live view of `R0` through `R15` (with `SP`, `LR`, and `PC` labeled). Values are shown as 8-digit uppercase hex. Changed values flash briefly so you do not miss updates during bursts.

### Flags Row

Shows `N`, `Z`, `C`, `V` condition flags and an **ARM / THUMB** mode pill. A bright pill means the flag is set.

### Disassembly

Next five instructions from the current `PC`, with the first one highlighted.

### Uploaders

- **Custom Hex**: Paste space-separated ARM machine code in hex
- **Select & Load .bin**: Upload a compiled bare-metal binary
- **Linux zImage + initrd**: Upload a kernel and ramdisk for Linux boot
- **Load APK**: Select an APK for the HLE Dalvik runtime

## Input Mapping

NekoDroid forwards browser input to MMIO registers so ARM programs can read keys and touch.

### Keyboard

The frontend listens on `document` so you do not need to focus any element. Arrow keys call `preventDefault()` so the page does not scroll.

| Browser key | Keycode sent to `INPUT_KEY` at `0x10000008` |
| --- | --- |
| ArrowUp / W | 38 |
| ArrowDown / S | 40 |
| ArrowLeft / A | 37 |
| ArrowRight / D | 39 |
| Space | 32 |
| Enter | 13 |
| Escape | 27 |
| Other keys | Standard `keyCode` value |

Key events are deferred by one frame to guarantee the ARM CPU sees each key for at least one full batch.

### Touch / Mouse

Events on the canvas are translated to framebuffer coordinates using `getBoundingClientRect()`.

| Event | Behavior |
| --- | --- |
| `mousedown` | Sends `touch_down` at translated coordinates. Initializes audio on first click. |
| `mousemove` while pressed | Sends additional `touch_down` events for drag tracking. |
| `mouseup` | Queues a `touch_up` for the next frame. |
| `mouseleave` while pressed | Sends a cancel event with coordinates `(-1, -1)`. |

The touch state is readable from two MMIO locations:

| Register | Address | Value |
| --- | --- | --- |
| `INPUT_TOUCH` | `0x1000000C` | `1` while pressed, `0` otherwise |
| `INPUT_COORD` | `0x10000010` | `[Y:16][X:16]` packed 32-bit coordinate |

### Audio MMIO

Programs can drive the Web Audio oscillator through two registers:

| Register | Address | Bits |
| --- | --- | --- |
| `AUDIO_CTRL` | `0x10000018` | Bit 0 = enable, bits 1-2 = waveform (0 square, 1 sine, 2 sawtooth, 3 triangle) |
| `AUDIO_FREQ` | `0x1000001C` | Frequency in Hz |

Audio initializes on the first canvas click. Programs should be ready for the API to start suspended.

## Upload Limits

APK uploads have a 32 MiB soft cap, enforced by both the file picker and the Rust APK loader. Kernel images, initramfs files, and bare-metal binaries use separate loading paths. This cap does not apply to them.
