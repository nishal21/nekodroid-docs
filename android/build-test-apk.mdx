NekoDroid ships with built-in test fixtures, but you can also author your own minimal APKs from Smali sources. This page shows you how to regenerate the committed fixtures using `cargo test`, how to write a minimal Smali program, and how to package it into a ZIP that NekoDroid's HLE interpreter can load.

## Regenerate fixtures with cargo test

The fastest way to rebuild `testdata/hello.apk`, `testdata/hello_println.dex`, and `testdata/bad.apk` is to run the in-tree test:

<CodeGroup>

```bash Bash
cargo test --lib write_fixtures_to_testdata
```

</CodeGroup>

This test calls `fixture::build_hello_apk()` and writes the bytes directly to `testdata/`. The resulting `hello.apk` contains:

- `classes.dex` with a single class `Lcom/nekodroid/Hello;`
- A text `AndroidManifest.xml` with package `com.nekodroid` and activity `Lcom/nekodroid/Hello;`
- No native libraries or resources

The `bad.apk` fixture is just the literal bytes `b"not-an-apk"` and is used to verify error handling.

<Note>
  You do not need Android Studio, Gradle, or the Android SDK to rebuild these fixtures. Everything is generated in pure Rust inside `src/android/fixture.rs`.
</Note>

## Author a minimal Smali program

If you prefer to write human-readable Dalvik assembly, you can use [smali](https://github.com/JesusFreke/smali) to assemble `.smali` files into `.dex` or `.apk`.

### Step 1: Write Hello.smali

Create a file named `Hello.smali` with the following source. It loads a string constant, invokes the HLE `println` stub, and returns.

<CodeGroup>

```smali Smali
.class public Lcom/nekodroid/Hello;
.super Ljava/lang/Object;

.method public static main([Ljava/lang/String;)V
    .registers 2

    const-string v0, "Hello from NekoDroid"

    invoke-static {v0}, Lnekodroid/Hle;->println(Ljava/lang/String;)V

    return-void
.end method
```

</CodeGroup>

<Info>
  NekoDroid's HLE host recognizes `Lnekodroid/Hle;->println` and `Ljava/io/PrintStream;->println` as the same logging stub. Using `Lnekodroid/Hle;` keeps your test code independent of the full `java.io` package.
</Info>

### Step 2: Assemble with smali

Install [smali](https://github.com/JesusFreke/smali) and run:

<CodeGroup>

```bash Bash
java -jar smali.jar assemble Hello.smali -o classes.dex
```

</CodeGroup>

This produces a `classes.dex` file containing the compiled Dalvik bytecode for your class.

### Step 3: Package into an APK

An APK is just a ZIP file with a specific layout. Create it with any ZIP tool:

<CodeGroup>

```bash Bash
zip hello.apk classes.dex
```

</CodeGroup>

For NekoDroid to read the package name and launcher activity, you can also add a minimal `AndroidManifest.xml`:

<CodeGroup>

```xml AndroidManifest.xml (minimal)
#nekodroid-manifest
package=com.nekodroid
activity=Lcom/nekodroid/Hello;
```

</CodeGroup>

```bash Bash
zip hello.apk classes.dex AndroidManifest.xml
```

<Warning>
  Do not add `META-INF`, `resources.arsc`, or `lib/` directories. NekoDroid ignores them, and they only increase file size toward the 32 MiB upload cap.
</Warning>

## Tips to stay within MVP opcodes

To ensure your APK runs in NekoDroid's HLE interpreter, follow these guidelines when writing Smali or generating DEX bytecode:

1. **Use only integer arithmetic.** Stick to `add-int`, `sub-int`, `mul-int`, and their `/2addr` variants. Floating-point opcodes are not implemented.
2. **Avoid exceptions.** There is no exception table support in the MVP interpreter. Keep control flow limited to `if-*`, `goto`, and method calls.
3. **Keep arrays one-dimensional.** `new-array`, `array-length`, `aget`, and `aput` work, but multi-dimensional or sparse arrays are untested.
4. **Invoke only HLE stubs or methods you define.** Framework calls outside the stub list will return `0` silently, which can hide bugs.
5. **Test with the arith fixture pattern.** If you want to verify arithmetic, model your test after the in-tree `build_arith_dex` fixture:

<CodeGroup>

```smali Smali (arith pattern)
    const/4 v0, 0x2
    const/4 v1, 0x3
    add-int/2addr v0, v1
    invoke-static {v0}, Lnekodroid/Hle;->printInt(I)V
    return-void
```

</CodeGroup>

This pattern computes `2 + 3 = 5` and logs `5` through the HLE `printInt` stub.

## Verify your APK in the browser

After packaging your APK, start the dev server and test it immediately:

<CodeGroup>

```bash Bash
wasm-pack build --target web
npm run dev
```

</CodeGroup>

Open [http://localhost:5173](http://localhost:5173), click **Load APK**, select your file, then click **Run APK (HLE)**. Check the logcat panel for your output. If the system log says `HLE Dalvik ran 0 steps` and the panel is empty, the VM most likely hit an unimplemented opcode. NekoDroid does not print the halt reason, so disassemble your DEX (for example with `baksmali`) and compare every instruction against the [Dalvik Opcodes](/reference/dalvik-opcodes) table.
