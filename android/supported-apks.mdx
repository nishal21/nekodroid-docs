NekoDroid's APK runner uses constrained high-level emulation (HLE) of Dalvik bytecode, not a full Android OS. This page lists what an APK must look like to run, which framework methods are stubbed, and which Android features are out of scope.

## APK requirements checklist

| Requirement | Details |
| --- | --- |
| Single `classes.dex` | Multidex is not supported. Only one DEX file inside the APK ZIP is read. |
| No JNI or native `.so` libraries | Native code never runs. Calls to `native` methods return `0` silently. |
| Entry point | The launcher class must have `main` or `onCreate`. `main` receives a null `String[]`. `onCreate` receives a fresh instance and no `Bundle`. |
| MVP opcodes only | Bytecode must use only opcodes from the [MVP Dalvik opcodes](#mvp-dalvik-opcodes) list. Unimplemented opcodes halt the VM. |
| Framework calls | Only stubbed HLE methods produce output. Other framework calls return `0` silently. |
| File size | 32 MiB maximum, enforced by both the web UI and `load_apk()`. |

## MVP Dalvik opcodes

The following opcodes are implemented. Any opcode outside this set causes the VM to halt with `AndroidError::UnimplementedOpcode`. The halt reason is stored internally but not written to logs.

| Opcode | Hex | Behavior |
| --- | --- | --- |
| `nop` | `0x00` | No operation |
| `move` / `move/from16` / `move/16` | `0x01` / `0x02` / `0x03` | Register moves |
| `move-object` / `move-object/from16` | `0x07` / `0x08` | Object reference moves |
| `move-result` / `move-result-object` | `0x0a` / `0x0c` | Capture return values |
| `return-void` / `return` / `return-object` | `0x0e` / `0x0f` / `0x11` | Method returns |
| `const/4` / `const/16` / `const` / `const/high16` | `0x12` to `0x15` | Load integer constants |
| `const-string` / `const-string/jumbo` | `0x1a` / `0x1b` | Load strings |
| `check-cast` | `0x1f` | Soft check, keeps object as-is |
| `array-length` / `new-array` | `0x21` / `0x23` | Array life |
| `new-instance` | `0x22` | Allocate HLE object stub |
| `goto` / `goto/16` | `0x28` / `0x29` | Unconditional branches |
| `if-eq` / `if-ne` / `if-lt` / `if-ge` / `if-gt` / `if-le` | `0x32` to `0x37` | Conditional branches (register pairs) |
| `if-eqz` / `if-nez` | `0x38` / `0x39` | Conditional branches (zero compare) |
| `aget` / `aput` | `0x44` / `0x4b` | Array get and put |
| `iget-object` / `iput-object` | `0x54` / `0x5b` | Minimal stub: no-op or `null` |
| `sget-object` / `sput-object` | `0x62` / `0x69` | Provides dummy `PrintStream` for `System.out` |
| `invoke-virtual` / `invoke-super` / `invoke-direct` / `invoke-static` / `invoke-interface` | `0x6e` to `0x72` | Method calls with HLE interception |
| `add-int` / `sub-int` / `mul-int` | `0x90` to `0x92` | 32-bit integer arithmetic |
| `add-int/2addr` / `sub-int/2addr` / `mul-int/2addr` | `0xb0` to `0xb2` | Two-address arithmetic |

If an unsupported opcode executes, `run_dalvik_batch` returns `0` for that batch and `get_apk_info()` shows `"halted": true`.

## Stubbed HLE framework methods

When the interpreter reaches `invoke-*`, it checks `HleHost::try_invoke` before searching the DEX file. The following methods are stubbed:

| Class | Method | Behavior |
| --- | --- | --- |
| `Landroid/util/Log;` | Any method (e.g. `d`, `i`, `w`, `e`) | Logs `[tag] msg` with tag defaulting to `App`, and appends to `canvas_text` |
| `Ljava/io/PrintStream;` | `println(String)` | Logs string to output buffer |
| `Lnekodroid/Hle;` | `println(String)` | Same as PrintStream |
| `Lnekodroid/Hle;` | `printInt(int)` | Converts to string and logs |
| `*TextView*` | `setText(String)` | Sets `canvas_text` and logs the message |
| Any class | `<init>` | No-op, returns `0` |
| Any class | `setContentView` / `setTitle` | No-op, returns `0` |
| Touch helpers | `getLastTouchX` / `getLastTouchY` / `isTouchDown` | Returns last forwarded touch state from `dalvik_touch` |

If a method is not in the HLE table and no matching DEX-encoded method exists, the call returns `Value::Int(0)` as a safe fallback.

## Manifest parsing

| Manifest format | What NekoDroid extracts |
| --- | --- |
| Text starting with `#nekodroid-manifest` or `package=` | `package=` and `activity=` lines (used by test fixtures) |
| Binary AXML (standard Android builds) | Best-effort package name only |
| Missing or unreadable | Package guessed from first DEX class; activity is first class containing `Hello`, `Main`, or `Activity`, otherwise the first class |

## Unsupported features

These are explicitly out of scope:

| Feature | Reason |
| --- | --- |
| Play Store apps | Require full ART, zygote, and Google services |
| Multidex (`classes2.dex`, etc.) | Only `classes.dex` is scanned |
| JNI / native `.so` libraries | No native loader or ARM syscall ABI |
| Full ART JIT / AOT | Only a register-based interpreter runs |
| SurfaceFlinger / hardware acceleration | Canvas drawing is limited to bitmap text blit |
| Binder / IPC | Binder is stubbed |
| Reflection, classloaders, exceptions | Not implemented in MVP interpreter |
| Floating-point opcodes | Only integer arithmetic is supported |

## Error behaviors

**Missing PK header or corrupt ZIP**

If the file does not start with `PK`, `load_apk_bytes` returns `AndroidError::NotZip` and the UI reports "APK load failed".

**Missing classes.dex**

A valid ZIP with no DEX file returns `AndroidError::MissingDex`. The UI shows "APK load failed (see console)".

**Unimplemented opcode during execution**

The VM sets `halted = true` and stores the reason internally. The batch stops, the UI reports "HLE Dalvik ran 0 steps", and the logcat panel shows only output from before the halt. Check `get_apk_info()` for `"halted": true`.

**No entry method found**

If the detected class has neither `main` nor `onCreate`, `launch_apk()` returns `false` and the UI logs "Launch failed".

**bad.apk fixture**

`testdata/bad.apk` is intentionally corrupt (`b"not-an-apk"`). It verifies that the error path returns quickly without panicking.
