NekoDroid can run minimal Android APKs inside the browser using a constrained HLE Dalvik runner. This page walks you through loading a fixture APK in the web UI, then shows how to control the same pipeline from JavaScript with the Wasm API.

## Run a fixture APK in the browser

These steps assume the NekoDroid dev server is running (`npm run dev`) and the debug panel is visible.

### 1) Load the APK

Click **Load APK** in the APK upload section and select a file. The UI calls `load_apk()` and logs a result like:

```text
APK loaded: 821 bytes, package=com.nekodroid, classes=1
```

Files larger than 32 MiB are rejected by both the web UI and `load_apk()`.

### 2) Inspect the APK info

After loading, the UI calls `get_apk_info()` and logs JSON such as:

```json
{"package":"com.nekodroid","activity":"Lcom/nekodroid/Hello;","apk_size":821,"classes":1,"halted":false,"steps":0,"logs":0}
```

### 3) Launch the HLE session

Click **Run APK (HLE)**. The UI performs:

```js
launch_apk();
const steps = run_dalvik_batch(50_000);
blit_dalvik_text_to_vram();
```

The render mode auto-switches to VRAM so the emulated screen shows any text the APK drew.

### 4) Read log output

The `apk-logcat` panel in the debug UI shows HLE output. For the built-in hello fixture the logs contain:

```text
Hello from NekoDroid
```

The arithmetic fixture logs `5`. If the panel shows `(no HLE logs)`, the APK either did not call a logging stub or halted before producing output.

### 5) Touch interaction

Click or drag on the canvas to forward touch events into the HLE runtime. Touch down and move set `touch_down=true` and update last coordinates. Touch release is deferred by one frame so the VM sees at least one full frame of press.

## How the APK pipeline works

Internally, loading and execution follows this order in Rust:

1. `load_apk_bytes` scans the ZIP for `classes.dex` and optionally `AndroidManifest.xml`.
2. The DEX is parsed into string, type, prototype, method, and class tables.
3. `launch_apk` detects the entry point, preferring `static main(String[])` then `onCreate`.
4. The register-based Dalvik interpreter steps one instruction at a time.
5. `invoke-*` instructions are intercepted by HLE stubs instead of invoking real Android services.
6. Text output is collected in a log buffer. `blit_dalvik_text_to_vram` draws `canvas_text` into video memory so the screen shows it.

## Wasm API for APK execution

You can drive the flow entirely from JavaScript instead of using the UI buttons.

### load_apk(apk_bytes): boolean

Load an APK into the HLE runtime. Returns `false` if the file is over 32 MiB or parsing fails.

```js
const bytes = new Uint8Array(
  await fetch('/hello.apk').then(r => r.arrayBuffer())
);
const ok = load_apk(bytes);
```

### get_apk_info(): string

Return a JSON string with package, activity, APK size, class count, halt state, step count, and log count.

```js
const info = JSON.parse(get_apk_info());
console.log(info.package, info.classes);
```

### launch_apk(): boolean

Find the entry method (`main` or `onCreate`) and push the initial VM frame. Return `false` if no APK is loaded or no entry method exists.

```js
if (!launch_apk()) {
  throw new Error('No valid entry point');
}
```

### run_dalvik_batch(count): number

Run at most `count` Dalvik instructions and return how many actually executed. The VM halts when `return-void` or `return` empties the call stack, or when an unimplemented opcode is hit. When an unimplemented opcode is encountered, the VM halts and this call returns `0`. The halt reason (`unimplemented opcode 0xNN at pc=N`) is stored internally but not added to the logs.

```js
const executed = run_dalvik_batch(50_000);
console.log(`Executed ${executed} Dalvik steps`);
```

### get_dalvik_logs(): string

Return all log lines collected by the HLE host, joined by newlines.

```js
const logs = get_dalvik_logs();
if (logs.includes('Hello from NekoDroid')) {
  console.log('fixture passed');
}
```

### blit_dalvik_text_to_vram(): boolean

Draw the current `canvas_text` into VRAM using simple block glyph placeholders. Returns `true` if text was present and written.

```js
if (blit_dalvik_text_to_vram()) {
  // switch render mode to VRAM
}
```

## Full scripted example

```js
async function runHelloApk() {
  const res = await fetch('/hello.apk');
  const bytes = new Uint8Array(await res.arrayBuffer());

  if (!load_apk(bytes)) return;
  const info = JSON.parse(get_apk_info());
  console.log('Loaded:', info.package, info.activity);

  if (!launch_apk()) return;
  const steps = run_dalvik_batch(50_000);

  const logs = get_dalvik_logs();
  console.log(`steps=${steps} logs=`);
  console.log(logs);

  blit_dalvik_text_to_vram();
}
```

## Touch forwarding via dalvik_touch

The browser UI forwards canvas mouse/touch events to both the ARM CPU MMIO registers and the HLE APK host:

```js
canvas.addEventListener('mousedown', (e) => {
  const [x, y] = canvasCoords(e);
  send_touch_event(x, y, true); // ARM CPU
  dalvik_touch(x, y, true);     // HLE VM
});
```

APK code calling `getLastTouchX()`, `getLastTouchY()`, or `isTouchDown()` reads the last values forwarded via `dalvik_touch`.
