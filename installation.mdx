This guide walks you through installing the required tools, building NekoDroid from source, creating production builds, and deploying the static output to any web host.

## Prerequisites

You need three tools installed on your system before building NekoDroid.

<Tabs>
  <Tab title="Rust">
    Install Rust via [rustup](https://rustup.rs/):

    ```bash
    curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
    ```

    Then add the WebAssembly target:

    ```bash
    rustup target add wasm32-unknown-unknown
    ```

    Verify with `rustc --version`. NekoDroid uses the 2024 edition.
  </Tab>
  <Tab title="wasm-pack">
    Install wasm-pack from [wasm-pack.rs](https://rustwasm.github.io/wasm-pack/installer/):

    ```bash
    curl https://rustwasm.github.io/wasm-pack/installer/init.sh -sSf | sh
    ```

    Or install via cargo:

    ```bash
    cargo install wasm-pack
    ```

    The first `wasm-pack build` compiles about 256 crates and can take 8 minutes. Subsequent builds are fast (1 to 2 seconds).
  </Tab>
  <Tab title="Node.js">
    Install Node.js 18 or later from [nodejs.org](https://nodejs.org/) or via your system package manager. Then verify npm is available:

    ```bash
    node --version
    npm --version
    ```
  </Tab>
</Tabs>

## Clone and Install

Once the prerequisites are in place, clone the repository and install JavaScript dependencies.

```bash
git clone https://github.com/nishal21/NekoDroid.git
cd NekoDroid
npm install
```

The `npm install` step fetches Vite 7.3.1, TypeScript 5.9.3, and the Wasm loader plugins.

## Build the Project

NekoDroid has two build targets: the Wasm module and the full production site.

### Development Build

For local development, build the Wasm module and start the Vite dev server:

```bash
wasm-pack build --target web
npm run dev
```

Open [http://localhost:5173](http://localhost:5173) in your browser. The dev server supports hot module replacement for TypeScript changes, but you must rebuild the Wasm module manually when Rust source changes.

### Available Scripts

| Script | Command | Purpose |
| --- | --- | --- |
| `dev` | `vite` | Start the development server |
| `build:wasm` | `wasm-pack build --target web` | Compile Rust to Wasm only |
| `build` | `npm run build:wasm && tsc && vite build` | Full production build |
| `preview` | `vite preview` | Preview the production build locally |
| `test` | `cargo test --lib` | Run Rust unit tests |

### Production Build

To create an optimized build for deployment:

```bash
npm run build
```

This performs three steps in sequence:

1. `wasm-pack build --target web` compiles the Rust crate with Link Time Optimization (LTO) enabled in release mode
2. `tsc` type-checks the TypeScript source
3. `vite build` bundles the frontend and outputs static files to the `dist/` directory

The resulting Wasm module is approximately 16 KB (plus the JS glue), and the full site is suitable for static hosting.

## Preview the Production Build

Before deploying, preview the production build locally to verify everything works:

```bash
npm run preview
```

This serves the `dist/` directory on a local port so you can test the optimized output.

## Deploy to Static Hosting

The `dist/` directory produced by `npm run build` is a fully static site. You can deploy it to any static web host.

### Important: Wasm MIME Type and Caching

WebAssembly files must be served with the correct `Content-Type: application/wasm` header. NekoDroid includes a `public/_headers` file that your host should respect:

```text
/*
  X-Content-Type-Options: nosniff

/*.wasm
  Content-Type: application/wasm
  Cache-Control: public, max-age=31536000, immutable
```

<Note>
  If your host does not support `_headers` (for example, GitHub Pages), add equivalent rules in your host's configuration panel or use a custom server with proper MIME type mappings.
</Note>

### Deployment Options

  </Card>

## Troubleshooting

<Accordion title="wasm-pack build fails with static_mut_refs error">
  Ensure you are using Rust stable with the 2024 edition. NekoDroid uses `AtomicU32` with `Ordering::Relaxed` instead of `static mut` references. If you see this error in your own fork, replace `static mut` patterns with atomics or `std::sync::OnceLock`.
</Accordion>

<Accordion title="Vite cannot resolve .wasm imports directly">
  Do not import `.wasm` files directly from TypeScript. Instead, import the JS glue generated by wasm-pack (`../pkg/nekodroid.js`), and call `wasm_memory()` after `init()` if you need direct memory access.
</Accordion>

<Accordion title="First build is very slow">
  The initial `wasm-pack build` compiles all Rust dependencies from source. This is expected and can take 8 minutes. Delete `target/` or run `cargo clean` if you want to force a full rebuild later.
</Accordion>

<Accordion title="Browser shows a blank page after deployment">
  Check that `.wasm` files are served with `Content-Type: application/wasm`. Use your browser's Network tab to inspect the response headers. If the type is `application/octet-stream`, the WebAssembly module will not instantiate.
</Accordion>

<Accordion title="Out of memory during Android boot">
  Increase the RAM allocation in `src/main.ts` by passing a larger value to `init_emulator()`:

  ```typescript
  init_emulator(512); // 512 MB
  ```

  The default is 128 MB, and the maximum is 4096 MB.
</Accordion>

## Verify Your Installation

Run the Rust unit tests to verify the build is healthy:

```bash
cargo test --lib
```

You should see all tests pass. The optional goldfish kernel tests are skipped if `test-images/zImage` is not present.
