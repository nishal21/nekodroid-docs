This page covers the tools and commands you need to build NekoDroid locally.

## Requirements

| Tool | Requirement |
| --- | --- |
| Rust | Stable toolchain with `wasm32-unknown-unknown` |
| wasm-pack | Builds the Rust crate and JavaScript bindings |
| Node.js | `^20.19.0` or `>=22.12.0`, required by the locked Vite version |
| npm | Installs the browser interface dependencies |

Install Rust from [rustup.rs](https://rustup.rs) and Node.js from [nodejs.org](https://nodejs.org). Then add the Rust target and install wasm-pack:

```bash Install build tools
rustup target add wasm32-unknown-unknown
cargo install wasm-pack
```

Check that the commands are available:

```bash Check installed tools
rustc --version
wasm-pack --version
node --version
npm --version
```

## Build and Run

<Steps>
  <Step title="Get the source">
    ```bash Clone NekoDroid
    git clone https://github.com/nishal21/NekoDroid.git
    cd NekoDroid
    npm install
    ```
  </Step>
  <Step title="Build WebAssembly">
    ```bash Build the Wasm package
    npm run build:wasm
    ```

    This runs `wasm-pack build --target web`. The generated bindings and binary live in `pkg/`.
  </Step>
  <Step title="Open the interface">
    ```bash Start Vite
    npm run dev
    ```

    Open the URL printed by Vite, normally [http://localhost:5173](http://localhost:5173). Rebuild the Wasm package after changing Rust source.
  </Step>
</Steps>

## Production Build

```bash Build and preview
npm run build
npm run preview
```

`npm run build` builds Wasm, checks TypeScript, and bundles the interface into `dist/`. `npm run preview` serves that output locally.

## Common Problems

**Vite reports an unsupported Node version:** use Node.js that satisfies `^20.19.0 || >=22.12.0`. A dependency accepting Node 18 does not mean the whole project supports it.

**The browser cannot load Wasm:** rebuild with `npm run build:wasm` and check the browser's network and console errors. Confirm `pkg/nekodroid.js` and `pkg/nekodroid_bg.wasm` were generated.

**An allocation fails:** `init_emulator(0)` requests 512 MiB of RAM. Browser memory limits can prevent large allocations. Use a smaller nonzero argument through the [JavaScript API](/reference/wasm-api).
