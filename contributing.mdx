This page covers how to contribute to NekoDroid, what kinds of changes the project accepts, and where to find detailed development instructions.

## Reporting issues

If you find a bug or have a question, open an issue on the [GitHub repository](https://github.com/nishal21/NekoDroid). When reporting a bug, include:

- The browser and version you are using
- The steps that trigger the issue
- Expected behavior and actual behavior
- Any relevant log output from the browser console or the logcat panel

## Pull requests

The project welcomes small, focused pull requests that change behavior for the constrained HLE Dalvik runner. Before opening a PR:

1. Verify your change against actual source behavior, not just documentation claims
2. Keep changes scoped to one concern per PR
3. Do not modify tracked demo binaries unless you are deliberately changing them
4. Do not stage local working copies, build artifacts, or journals

## What never belongs in a commit

Do not run `git add .` or `git add -A`. Stage only files you intend to change.

Never commit these directories or files:

| Path | Reason |
| --- | --- |
| `browser-droid/` | Local nested working copy |
| `pkg/`, `target/`, `node_modules/`, `dist/` | Build artifacts |
| `test-images/` | Local test images |
| `*.zImage`, `*.img`, `*.cpio.gz` | Kernel images |
| `learning-journal.md`, `handoff-devlog.md` | Personal notes |
| `.cursor/`, `.env*` | Editor or environment files |

Demo binaries that should not be modified unless deliberate:

- `snake.*`
- `theremin.*`
- `vram_test.*`
- `input_test.*`
- `program.*`

## Documentation to keep in sync

If you change the HLE path or Dalvik interpreter, update the matching files in `docs/`:

| File | Purpose |
| --- | --- |
| `docs/SUPPORTED_APKS.md` | Which APKs the HLE path can run |
| `docs/OPCODE_MVP.md` | Checklist of implemented Dalvik opcodes |
| `docs/REFERENCES.md` | External specs: DEX format, Dalvik bytecode, ART interpreter, smali |

## Scope

NekoDroid is a constrained HLE Dalvik runner, not a full Android or ART emulator. Prefer small test APKs without native libraries.
